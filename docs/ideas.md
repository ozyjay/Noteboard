# Noteboard — Ideas

## Purpose

This is a human-maintained inbox for exploratory ideas, feature suggestions, UX observations and questions. Ideas can be incomplete, speculative, contradictory or not yet technically feasible. An entry is not an approved requirement or an instruction to implement it.

**Capture → Explore → Refine → Decide → Implement**

## How to use this file

- Add an idea under a simple descriptive heading, in your own words.
- Include examples, scenarios or questions if they help explain it.
- Refine it over time, or explore it with Codex before deciding what to implement.

There are no required fields, identifiers, statuses or priorities. A few sentences are enough.

For example, an optional starting point could be:

> ### Something I noticed while exploring
>
> Describe what happened, what you hoped would happen and any questions you want to explore.

## Ideas inbox

> ### What about supporting RAG and web search?
>
> We probably need additional provider agnostic layer(s) that provide functionality such as RAG and web search.

## Review and promotion

Only following explicit user direction may an idea become a GitHub Issue or a change to the product plan, roadmap or architectural decisions. Implementation also requires explicit user direction. Preserve the original idea unless the user explicitly requests its removal or modification.

This inbox holds exploratory suggestions; the product plan holds agreed vision and requirements, the roadmap tracks implementation priorities and progress, decisions record established design choices, and GitHub Issues hold actionable development tasks.
