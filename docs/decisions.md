# Initial decisions

- **macOS credential unlock:** use native data protection Keychain user-presence access control so macOS offers Touch ID with password fallback, and reuse the unlocked vault key for the app session. Preserve legacy credentials through validated, atomic migration; failures must leave the old file available for retry. Require profile-backed signing and Keychain entitlements rather than a standalone biometric prompt or an insecure fallback. Other platforms retain secure Electron storage.

- **Board names:** Rename Board beside the heading opens a name editor with Save, Cancel and Escape. Right-clicking a Board in the sidebar (or pressing Shift+F10/the context-menu key) offers Rename and Delete for that Board without switching the open Board. Delete retains its confirmation; deleting an inactive Board leaves the open Board and its drafts intact. Names must contain non-whitespace text and are limited to 200 characters. Renaming updates Board metadata through normal local persistence, leaving Notes, prompts, responses and provenance intact. An empty Board with a custom name keeps it when its first Note is created; the default Untitled inquiry still takes its first question as its name.

- **Edge labels:** show exact connection text in a two-line, width-bounded label, with visual ellipsis for overflow. Hovering the Edge or focusing its label reveals a viewport-bounded, scrollable full-text preview at screen text size. Down arrow moves focus into the preview; Escape dismisses it. Labels remain hidden at distant zoom until hovered or focused. Clicking a label or Edge, pressing Enter on the label, or choosing Open source Note retains the source-version and Highlight navigation. This is presentation only; stored Highlights are unchanged.

- **Detailed Notes:** a side reading panel preserves the Board arrangement and offers a comfortable selectable reading surface. A human-controlled expand/collapse action fills the workspace body for focused reading without moving Notes.
- **Graph Tab navigation:** each canvas Note is one Tab stop, with Enter or Space to open it and a visible focus outline. Its checkbox, title, reading action, Peek control and Layout menu contents stay out of the Tab sequence while retaining mouse and programmatic focus behaviour. Layout menus close when focus leaves them. React Flow wrappers add no duplicate Note stops. Canvas toolbar controls, Edge source navigation and the Note reader retain their own keyboard interactions.
- **Edge arrows:** every Edge points from its parent to its child, including imported continuations. Arrowheads retain their screen size as zoom changes and stop just before the child's connection handle so the Note cannot obscure them. Lines retain their screen stroke width, themed colour and continuation dash styling. Four-sided routing and source-Highlight navigation remain unchanged; arrow rendering belongs to `HighlightEdge`.
- **Canvas Note hierarchy:** the Note title/prompt is always the dominant element in every style: it appears first, uses larger and heavier heading text in the primary text colour, and is followed by a smaller, regular-weight Takeaway in the secondary text colour. Sticky and Studio retain their Takeaway labels; Blueprint keeps its Takeaway behind the Peek control. Arrange mode retains the prompt as its main visible content. This is presentation only and does not change saved prompts, responses or Takeaways.
- **Appearance:** app-wide light/dark/system themes, curated accent colours, reading text sizes, separate interface and reading font choices, and an optional canvas grid. Standard interface typography and sans-serif reading remain the defaults; monospace uses installed Consolas, Menlo or Monaco, while serif reading uses Georgia. Fonts are local fallbacks; maths retains KaTeX typography and code remains monospace. Changes preview immediately; Cancel restores saved preferences. Preferences persist independently of Boards in SQLite (localStorage in browser preview).
- **Sticky Notes and composing:** sticky style uses paper grain, translucent adhesive tape, curled corners and lifted shadows without rotating text or connection anchors. Enter sends the Note prompt; Shift+Enter inserts a new line. Composing text through an IME, held-key repeats, empty prompts and in-progress requests do not submit.
- **ChatGPT controls:** automatically load models when ChatGPT and a connected account are selected, and show their display names. Persist each account’s discovered catalogue and reported thinking-level/default metadata independently of Boards, settings and credentials; reuse it across restarts, settings, new Notes and revisions. Refresh models replaces it only after successful discovery, and sign-in/sign-out invalidates it. Thinking pickers offer Model default plus the selected model’s advertised levels in service order. Missing level metadata stays unknown; unrecognised future levels are retained but disabled, and an existing unlisted override remains visible as unconfirmed rather than being silently changed. Thinking effort defaults to the model's own setting; explicit overrides are recorded with generated responses and synthesis. The service remains authoritative about model-specific support; rejected requests fail visibly without a silent replacement.
- **Note modes:** the visible canvas Note mode control offers Auto (follow zoom), Arrange and Read, alongside a live hint explaining the effective mode and drag target. Auto uses compact Arrange cards at zoom ≤ 0.55 and detailed Read cards above it. Manual choices override zoom until changed; the choice lasts for the application session across Board navigation, then resets to Auto on reopening. Changing modes never moves Notes or changes their data. Mode changes are unavailable during movement or tidy previews.
- **Graph arrangement:** drag a Note's header in Read mode, or anywhere on its card (including its title) in Arrange mode, to move that Note freely without changing its parent or Highlight. The Layout menu and synthesis checkbox remain separate interactive controls. Its Layout menu offers explicit Move Note and Move with descendants modes, with arrow keys (10 canvas units, Shift: 50; with snapping: 24, Shift: 120), Enter to apply keyboard movement and Escape to restore. Releasing a pointer drag commits immediately; movement has no Done/Cancel buttons, and layout undo remains available after dropping. Branch moves translate all descendants equally. Alignment guides appear within six screen pixels; movement stays free unless Snap to grid is enabled. Manual overlaps are permitted; no neighbouring Note is pushed aside.
- **Arrangement shortcuts and snapping:** visible A and G hints accompany the Note mode and Snap to grid controls. A toggles the effective Arrange/Read mode; G toggles snapping. Shortcuts ignore typing, composition, repeats, Ctrl/Cmd/Alt combinations, reader surfaces, dialogues and active layout operations. Snapping defaults off and lasts for the application session. Enabling it reveals the 24-unit grid without changing appearance settings or moving existing Notes. Pointer and keyboard moves snap the selected root; whole-branch movement translates descendants by the same delta, preserving relative spacing. Automatic child placement and Tidy retain their collision-aware geometry. Layout undo restores the exact previous positions.
- **Child placement:** each Note has an optional Right/Below preference for future children (missing means Right); dragging and tidying never change it. Place using normal-detail measured card bounds, a 90-unit parent gap and 60-unit collision spacing; scan down for Right or right for Below. Newly created children are measured and placed before canvas interaction. Existing positions remain unchanged on zoom, appearance changes and reopening.
- **Connections and tidying:** four-sided connectors adapt to relative card centres, preferring the horizontal axis on ties. Tidy branch fixes the selected root and arranges descendants recursively using each parent's growth direction and current spatial sibling order (Board order breaks ties). It reserves subtree bounding boxes and shifts child blocks past fixed outside obstacles. Apply commits the preview; Cancel/Escape discards it. Other graph-changing controls are unavailable during preview; panning and zoom remain available. No automatic whole-Board rearrangement, reparenting or obstacle-avoiding Edge routing.
- **Layout history:** explicit Undo layout/Redo layout controls retain up to 50 layout operations per Board in the current session, including direction changes. History patches positions/preferences onto current Notes without restoring content. Adding/removing Notes or Edges clears that Board's history. Switching Boards preserves histories but cancels transient movement/previews; application reopening clears history. Text-editor undo remains separate.
- **Deletion:** the Board toolbar deletes the current Board and its artefacts after confirmation. The Note reader deletes a Note and all its descendants, with the affected count shown before confirmation; no automatic reparenting. Existing synthesis retains read-only source snapshots and document revisions. Deleting the root clears the tree; deleting the last Board opens a fresh empty Board. Deletion has no undo.
- **Note titles and navigation:** Notes have an optional human-edited title (up to 200 characters), displayed on the canvas and reader. Double-click the reader heading (or focus it and press Enter/Space) to edit the title inline. Enter or moving focus away saves; Escape cancels. Clearing it restores the prompt as the display title. Original prompts and response versions remain immutable; titles do not change inference context. The reader links to the previous (parent) Note and every subsequent (direct child) Note, including imported continuations. Returning to the parent reveals the connection's source Highlight when available.
- **Anchoring:** rendered-text snapshots plus exact DOM Range offsets. Source responses are immutable; a new response would need a new version ID rather than editing an anchored response.
- **Direct text editing:** double-clicking the displayed prompt or response in the Note reader opens its revision editor for the viewed version. Keyboard users can focus the text and press Enter. Selecting response text still offers branching; source links keep their navigation action. The reader heading edits the display title inline; the separately labelled Prompt retains prompt revision editing.
- **Response self-review:** Sanity check & improve sends the viewed response and its conversation with an editable follow-up prompt, then appends a generated version to the same Note. It retains the viewed version's question and ancestry, complete effective request, and revision base. Generated history includes earlier review turns; imported originals use visible history without inventing historical requests. Previous responses, Highlights and synthesis sources remain unchanged. No automatic branches, external verification or silent context reduction is implied.
- **Per-Note generation choices:** new root and Highlight-branch composers start with saved provider model and thinking effort, with request-only overrides. Model changes reset effort to Model default. Discovery and inference use the existing bridge; overrides do not change provider defaults or earlier Notes. Only ChatGPT exposes thinking effort, and failed requests retain the draft without silently changing the requested level.
- **Web research and file inputs:** ChatGPT Notes and revisions expose optional web search, enabled by default, and inline document attachments. Record requested/actual search, completed tool actions, citation ranges and source URLs without rewriting original responses. Preserve attached bytes in immutable version inputs and effective context, including ancestral files, revisions, exports and reopening. Open validated HTTP/HTTPS sources only through a narrow main-process bridge. Limits and unsupported providers fail visibly without dropping files, changing tools or choosing a billed fallback. Synthesis uses recorded source Notes without fresh search. Board schema 4 prevents older clients from silently discarding the new provenance.
- **Note revisions:** Edit prompt and regenerate, Regenerate response and Edit response each append an immutable version. A revised prompt belongs to that version; the original Note prompt remains intact. Human edits retain a source-version reference and are explicitly labelled with no invented inference metadata. A version picker controls reading and new Highlight branches; the canvas and new synthesis use the latest version. Existing branches pin the complete ancestral path and existing artefacts retain their source versions. Regeneration uses the viewed version's ancestry and current configured provider/preferences, with optional model discovery/selection; changing models clears the request's thinking-effort override. No existing descendants are regenerated automatically. Failed or cancelled requests add no revision.
- **Answers, orientation and Takeaways:** answer naturally and lead with the useful conclusion. Include broader context or **Where this fits** only when helpful; do not require a concluding Takeaway section. Follow-ups can connect to the selected passage and ancestral conversation; unrelated branches remain excluded. If an explicit Takeaway is absent, use the first substantive paragraph as a lightweight canvas fallback, never the final sentence or an additional inference request. Users can correct it through the reader’s collapsed **Edit takeaway** control. Corrections affect the Board Takeaway only; original responses remain unchanged.
- **Custom instructions:** editable local settings apply to future Notes and generated synthesis across providers. Defaults favour Australian English, concise natural answers, proportionate detail, epistemic discipline and clear recommendations. Save commits changes, Cancel discards the draft, Restore response preferences restores the default draft, and blank text leaves basic app guidance. Record the exact instructions in effective context and include them in budget checks without trimming history. Board exports therefore include instructions used for generation, while the settings record stays local. No ChatGPT personalisation/project access or browsing capability is implied. Personal workspace boundaries can be entered by the user; none is silently added.
- **Synthesis:** Markdown editing and rendered preview are the structured editor MVP. Regeneration creates another artefact; saved edits append revisions. Earlier versions remain available.
- **Maths and reading:** Notes and synthesis use locally bundled KaTeX, with trusted commands disabled and bounded expansion. Synthesis opens in formatted preview; Edit exposes Markdown/LaTeX source. Equation selections preserve full equations and their exact LaTeX alongside rendered anchors. Older rendered anchors reopen with the original renderer rather than changing their text surface.
- **Context:** show estimates and configured budgets, check Ollama model capability before requesting inference, and reject requests that exceed estimates. Estimates may differ from provider tokenisation; exact token budgeting is future work.
- **Providers:** implement Ollama first, plus a clearly labelled synthetic interaction provider. ChatGPT plan usage uses the documented local-app OAuth flow with explicit consent and OS-encrypted credentials. Account-specific models and Responses streaming share the provider boundary; separately billed APIs remain unimplemented. Live ChatGPT eligibility and inference require user-directed validation.
- **Persistence:** atomic Board JSON snapshots in SQLite, independent settings table, Board JSON schema version 4 with deterministic in-memory migration of versions 1–3. Account model catalogues use a separate, additively created SQLite table; existing Board/settings records remain unchanged. ChatGPT credentials and host/account registrations live in a separate OS-encrypted, atomically replaced file; exports contain no credentials or model catalogues. Existing Boards remain readable with their original provenance. Version 4 exports require this attachment-aware app version, so older builds cannot silently discard revised prompts or ancestry pins.
- **Skills:** keep a small repository-specific skill under `skills/` and reference it from AGENTS.md. The managed workspace does not allow writing `.agents/`; no global agent configuration is changed.

- **ChatGPT import:** local text-only export import preserves one explicitly chosen path as a Note chain. Chronological continuation connections do not require Highlights; retrospective anchors are explicit human annotations. Imported versions distinguish known source metadata from unknown original inference context. No account history synchronisation, automatic instruction application or AI Highlight proposals.

- **Workspace density:** a 56 px toolbar contains one truncated Board title with full-title tooltip, Rename, Consolidate and a labelled More menu for secondary actions. A 40 px second row retains Explore/Synthesis and counts. The sidebar starts open at 220 px (200 px at narrower desktop widths). The reader defaults to 40% of workspace width, targeting 420–640 px within available-space limits; manual resizing overrides the default for the current reader lifecycle. Layout changes preserve the mounted canvas and its viewport and do not add persisted preferences.
- **Submission and focused reading:** submitting a new Note hides the composer controls and shows the question, provider-reported activity, elapsed time, Stop and streamed provisional text. Show thinking/searching only when supported by received events, otherwise retain a generic status; do not invent reading stages, progress percentages or reasoning text. Demo output/activity stays labelled synthetic. Completed Notes open in a reading view with workspace chrome hidden and versions/editing collapsed. Back to Board restores the normal workspace; its canvas stays mounted. Partial output cannot create Notes or Highlights, and failed/cancelled requests restore the draft and request-local choices. This changes transient UI only, not generation context, saved provenance or response DOM anchoring.
